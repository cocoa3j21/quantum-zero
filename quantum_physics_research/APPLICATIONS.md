# QuantumZero「失敗した仮説」からの応用再構成

**前提（INVESTIGATION.md より）**

- **【事実】** v1 の「ゼロ除算を量子状態にすれば情報は失われない」は、数学・物理学として成立しない。
- **【整理】** 捨てるのは **「物理学の主張」** であり、次の **設計構造** は v2 で残っている:
  - 異常を保持する
  - 未定義を演算で伝播する
  - 後から `resolve()` する
  - BH 情報問題は **比喩** に降格する
  - 円周率・無理数の **非周期性**（数学的事実）を **リトライ間隔など** に転用しうる

本書は 3 つの応用案のたたき台です。**【事実】**＝標準数学・文献、**【推測】**＝未検証のアイデア。

## 応用案 1: 円周率を使った非周期的リトライ戦略

### 仮説の一言

API が 429（レート制限）や一時障害で **0 除算に相当する「処理不能」** になったとき、`AuditState` で異常を記録しつつ、**待ち時間に π の小数展開由来の非周期ジッタ** を入れて、同期リトライ嵐を避ける。

### 物理学として正しいか

| 判定 | 理由 |
|------|------|
| **該当なし（誤りでも正しくもない）** | これは **ソフトウェア工学** の話。π を使う根拠は **数論** にある。 |

**【事実・数学】** π は **無理数**（整数比で表せない）。十進小数は **周期を持たず** 続く（[Wikipedia: Pi](https://en.wikipedia.org/wiki/Pi)）。

**【事実・数学】** 数列 \(\{n\pi \bmod 1\}_{n=1}^\infty\)（小数部分）は **等分布（ergodic）** に近い振る舞いをし、擬似ランダムな間隔の理論的動機になる（**ウェイルの準モンテカルロ法 / Weyl sequence** として知られる）。これは物理学の「量子状態」ではなく **数の性質の利用**。

**【推測】** 「π だから宇宙と同相」などの物語は **物理学的主張にしない**。

### プログラミングとして使えるか

**はい（条件付き）。** 指数バックオフ + ランダムジッタの変形として実装可能。既存の `safe_divide` + `resolve()` と **パイプライン層** を組み合わせる。

### 検証方法

1. **単体テスト:** 連続 \(n\) で生成した待ち秒が **固定周期にならない**（一定窓で同じ値が無限反復しない）。
2. **シミュレーション:** 多数クライアントが同時リトライするモデルで、π ジッタあり/なしの **衝突率（同時再送率）** を Monte Carlo 比較（結果は **実装ごとに計測** すること）。
3. **運用テスト:** スクレイピング等で 429 時、`AuditState.to_log()` 行数と成功再開率をログ集計（本番前はステージング）。

### Python 実装イメージ

```python
# 新規モジュール例: retry_pi.py（未実装・イメージ）
import math
from decimal import Decimal, getcontext
from quantum_zero_v2 import safe_divide, AuditState

getcontext().prec = 50  # π 桁を少し取る

def pi_jitter_seconds(attempt: int, base: float = 1.0) -> float:
    """attempt 回目の待ち = base * (0.5 + fractional_part(attempt * pi))"""
    frac = (Decimal(attempt) * Decimal(str(math.pi))) % 1
    return base * (0.5 + float(frac))


def fetch_with_audit(numerator: float, divisor: float) -> float:
    value = safe_divide(numerator, divisor)
    if isinstance(value, AuditState):
        for attempt in range(1, 6):
            time.sleep(pi_jitter_seconds(attempt))
            if divisor != 0:  # 再試行条件は呼び手の責任
                break
        return float(value.resolve(default=0.0))
    return float(value)
```

### Zenn タイトル案

- 「ゼロ除算は諦めない：AuditState と π ジッタでリトライの同期を崩す」
- 「量子状態ではなく監査状態でスクレイピングを生き残る」

### 期待される読者の反応

- ポジティブ: 「429 地獄に出口」「失敗した BH デモが実務ノウハウになった」
- 批判: 「結局はランダムバックオフの変形では」「π は演出では」→ **事実として認め、ウェイル列の参考文献を書く**

### 失敗する可能性

- **待ちが長すぎて SLA 違反**
- **π 桁計算コスト**（通常は `math.pi` と `frac` で足りる）
- **divisor==0 の業務エラー**をリトライで誤魔化し、根本原因を隠す
- 「π で量子力学」を再び匂わせると **再び物理誤解を招く**

## 応用案 2: ブラックホール情報パラドックスを模した監査ログ

### 仮説の一言

「イベントホライズン（事象の地平線）」= **いま測れないが記録だけ残す境界** とみなし、0 除算や失敗は **AuditState** に閉じ込め、放射（`to_log()` 出力）だけを外に流し、**page 時間**（監査上の閾値）を超えたら `raise_if_undefined()` で人間に渡す。

### 物理学として正しいか

| 判定 | 理由 |
|------|------|
| **比喩としてのみ正しい** | 実 BH の情報問題は **量子重力・ユニタリ性** の未解決領域（INVESTIGATION §3）。 |

**【事実】** 情報は「ログ1行」では保存されない。ホーキング初期像では **熱的放射** が **相関情報を乏しく** 見せうる（専門家の間で解釈は発展中）。

**【整理】** コードの `to_log()` は **CSV 監査** であり、**ページ曲線も島も再現しない**。「情報パラドックスの解」ではない。

### プログラミングとして使えるか

**はい。** v2 が **すでに** `to_log()` / `to_dict()` / `resolve()` を持つ。ここが **最もそのまま製品化しやすい**。

### 検証方法

1. pytest 拡張: パイプライン入力に 0 除算を混ぜ、**出力ログ行数 = 異常イベント数** を検証。
2. **リプレイテスト:** 保存した TSV から同じ `resolve` ポリシーで再計算し、結果が一致するか。
3. **表現の監査:** ドキュメントに「物理学の情報保存ではない」と明記しているか人間レビュー。

### Python 実装イメージ

```python
# 監査パイプライン（イメージ・v2 拡張）
from quantum_zero_v2 import safe_divide, AuditState

class HorizonLogger:
  """比喩: BH 外へ「放射」するのは to_log() 行のみ。"""

  def __init__(self, page_time_sec: float):
      self.buffer: list[str] = []
      self.page_time_sec = page_time_sec
      self.t0 = time.monotonic()

  def step(self, dividend, divisor):
      r = safe_divide(dividend, divisor)
      if isinstance(r, AuditState):
          self.buffer.append(r.to_log())
      return r

  def finalize(self, last_state):
      if isinstance(last_state, AuditState):
          if time.monotonic() - self.t0 > self.page_time_sec:
              last_state.raise_if_undefined()  # 人間・バッチへ
      return self.buffer
```

### Zenn タイトル案

- 「ブラックホールに情報は残らないが、監査ログには残る：QuantumZero v2 の正しい読み方」
- 「情報パラドックスを DB に移植しない — AuditState で学ぶ失敗の記録」

### 期待される読者の反応

- ポジティブ: 「比喩と実装の線引きが気持ちいい」「v1 の反省が v2 で活きている」
- 批判: 「メタファーが長い」「監査なら OpenTelemetry でよい」→ **標準ツールとの差分表** を書く

### 失敗する可能性

- 読者が **「BH 問題を解いた」** と誤解
- `resolve(0)` 乱用で **静かなデータ欠損**（pipeline テストで既知）
- 比喩に夢中して **運用要件（PII、保持期間）** を満たさない

## 応用案 3: 全宇宙回転仮説とゼロ除算をつなぐ思考実験

### 仮説の一言

銀河回転曲線の計算で **\(r\to 0\)** や **角速度のゼロ除算相当**（例: \(\omega = v/r\)）が出たとき、AuditState で **特異点を記録** し、ワークスペースの `universal-rotation-hypothesis` と **「中心での定義域」** を並べて議論する。

### 物理学として正しいか

| 判定 | 理由 |
|------|------|
| **標準宇宙論・動力学の主張としては未確立** | 「全宇宙回転」は **作者の探索的シミュレーション**（`Labs/universal-rotation-hypothesis`）であり、教科書的標準モデルではない。 |

**【事実】** ニュートン重力の点質量モデルでは \(r=0\) で力・速度の定義に **特異点** が出る。これは **数式の定義域** の問題（極限と中心点は別、INVESTIGATION §1）。

**【推測】** 「宇宙全体が回転しているから 0 除算が許される」などの結論は **導けない**。つなぎは **コード上の safe_divide と Newtonian \(v/r\) の可視化** までに留める。

### プログラミングとして使えるか

**限定的に。** シミュレーションの **ガードレール**（中心格子点で `AuditState` → `resolve` またはスキップ）としては使える。**物理モデルの正当化には使えない。**

### 検証方法

1. `rotation_curve.py` の \(r=0\) グリッド点で、従来は例外か NaN かを記録し、AuditState 経路と比較。
2. **科学検証は別ルート:** 観測データとのフィットは既存パイプライン（URH プロジェクトのテスト）に任せ、QuantumZero は **数値安定性の層** とラベル付け。
3. **文献レビュー:** 標準的銀河回転曲線の説明（ダークマター・MOND 等）と **混同しない** 章を Zenn に書く。

### Python 実装イメージ

```python
# 思考実験用ラッパ（イメージ）
from quantum_zero_v2 import safe_divide, AuditState

def angular_speed(v_kms: float, r_kpc: float):
    """ω ∝ v/r。r=0 は数学的特異点 → AuditState 化（物理解釈は別）。"""
    state = safe_divide(v_kms, r_kpc)
    if isinstance(state, AuditState):
        return state.to_dict()  # シミュレーションは中心セルをスキップ
    return state
```

- 「銀河の中心で 0 除算したら — 回転曲線と AuditState の思考実験」
- 「全宇宙回転仮説とは別の話：数値特異点を記録するだけ」

### 期待される読者の反応

- ポジティブ: 「2 つの趣味プロジェクトがつながった」
- 批判: **物理 YouTuber / 専門家からの誤解指摘** が最大。タイトルに **「思考実験」「未検証仮説」** が必須。

### 失敗する可能性

- **最高リスク:** 読者が QuantumZero を **宇宙論の証拠** と誤る
- URH 自体の科学評価と **巻き添え**
- \(r=0\) は観測物理では通常 **到達しない** — デモが **非現実的** と見える

## 最も検討価値がある応用案

**選定: 応用案 2（ブラックホール情報パラドックスを模した監査ログ）**

### 理由

1. **【コードの事実】** v2 の `AuditState` / `to_log()` / `resolve()` が **すでに要件の核** を満たしている。新規物理主張を増やさない。
2. **【整理】** INVESTIGATION が推奨した転換点（「物理を主張しない」「異常を記録する」）と **完全一致**する。v1 の失敗を **正直な物語** にできる。
3. **比喩の使い方が教育価値が高い:** 「BH では情報はこう議論される → じゃあアプリでは **ログと resolve で何を保存するか**」という **二段構成** が Zenn で書きやすい。
4. **誤解リスクをコントロールしやすい:** 記事冒頭で「パラドックスの解決ではない」と1段落書けば、専門家批判を **先回り** できる（案 3 は難易度が高い）。
5. 案 1 は有用だが **π は付加価値** であり、QuantumZero の「失敗から学んだ核」より **一般的バックオフ** に見えやすい。案 2 のあとに **続編** にするのが自然。

### QuantumZero の失敗を価値ある研究に変えるには

| 捨てる | 残す | 公開の型 |
|--------|------|----------|
| 「量子状態」「\* 0 で情報復元」 | 異常オブジェクト + 明示 resolve + 監査ログ | **設計パターン記事** + pytest 仕様ロック |
| 物理学の正しさの主張 | BH / QFT への **比喩（図1枚）** | INVESTIGATION + APPLICATIONS を脚注 |
| v1 を消す必要はない | v1 を「アンチパターン教材」 | テストの xfailed を「未来の TODO」 |

**【整理】** 価値ある研究 = **「未定義をどう扱うか」のソフトウェア実験** であり、**量子論のシミュレーションではない**。その線引きが書けた時点で、失敗した仮説は **教材資産** に変わる。
